## CSV review and confirmation

CSV follows select/paste, validate, review, confirm replacement. Validation uses the established parser and scientific-document validator without committing state. Review exposes parsed rows, count and prior dataset size, roles, analytes, time range and anchor, native units/matrices, SD availability, censoring and alternative-matrix factors/sources. Row counts remain limited to 200; parser text limits and the 200,000-byte upload limit are retained.

A preview key includes exact CSV text, anchor, entered source, committed observation content/source and historical notes. Any dependency change invalidates confirmation immediately. Confirmation checks the key again and reparses current inputs, while preserving unrelated current fitting/sampling configuration. Async file reads use a sequence token so a delayed upload cannot overwrite subsequently pasted text. Bulk replacement is a distinct atomic history action. Clear and synthetic replacement identify the affected dataset in a keyboard-operable confirmation dialog. Individual removal names the row and retains immediate Undo.

## Scientific document schema 1.1.0

The scientific document advances from 1.0.0 to 1.1.0. Each validated observation has conversionSource, a string of at most 1,000 characters. The document has legacyConversionNotes, a string of at most 2,000 characters. Existing observationSource remains the user-authored dataset source, with its existing 2,000-character limit. Manual alternative-matrix entry requires a factor and source. CSV accepts the optional conversion_source column; existing CSV without that column remains valid, and missing row-specific provenance is displayed explicitly. Dataset notes remain applicable and conversion assumptions remain unverified.

Migration clones and validates legacy documents. Recognised generated descriptions of the form “Matrix conversion for ID: matrix × factor → model-matrix. assumptions” move into labelled historical notes. The last description matching an active row's ID, matrix, factor and canonical analyte matrix supplies that row's active source. Other authored text is preserved. Historical notes may refer to superseded or deleted rows and never supply an unqualified active conversion. Unrecognised free-form material remains dataset text and may require human provenance review. Edits replace row-associated assumptions; native-matrix replacement clears them; deletion removes them. Undo, session histories, exports, recovery and reports preserve the structured fields.

The session wrapper remains 1.1.0, scenario schema 0.8.2, scientific workbench algorithms 1.0.0, PK engine 0.4.4, constants 0.3.0, reference profile reference-1.60 and evidence revision 2026-10-28.1. Build metadata explicitly identifies scientificDocumentSchemaVersion 1.1.0. Existing v2.0/v2.1 scientific documents migrate through the same validation path; imported scientific result records retain their original captured keys and require recomputation before application. Older applications cannot interpret the new scientific schema.

Imported editing archives are validated and deduplicated with newly imported history. A 120-entry archive limit and the existing 8 MiB project limit bound growth; overflow rejects the import before mutation. This preserves previously imported provenance across subsequent session round trips. Ordinary current history retains its existing 60-entry limit. Explicit scientific confirmations bypass typing coalescence; ordinary field-edit coalescence is preserved.
