# v2.1.0 — UX consolidation and interaction coherence

## Audit and boundaries

The starting production commit was b8aa8bb903795761c454cd4c07c6892b54d6ce10. Its generated build opened Session → Inputs, rendered the original BAC ring and input concentration graph, and matched the official deployment fingerprint d9edfaeb32365dd3141a518c4d7ef05ceddefb17458fa6a8613253cbeb4ffea3. The audit exercised that generated interface locally and verified the public hosted, standalone and service-worker bytes.

The four workspaces and hash routes are retained. Default (dfv_1), Detailed (dtv_2) and Expert (xpv_3) remain the only scientific-depth settings. Their effects remain independent of explanation support, reading density, focus, appearance and motion. Application identity advances to 2.1.0. PK engine 0.4.4, constants 0.3.0, scientific schema/workbench 1.0.0, scenario schema 0.8.2, session wrapper 1.1.0, model profile reference-1.60 and evidence revision 2026-10-28.1 retain their identities.

## Scenario construction and accepted state

Session → Inputs remains the fresh-browser and installed-app entry. The retained person and drink editors preserve templates, volume/composition representations, direct masses, quantities, event editing and schedule access. The BAC ring and input graph retain their underlying calculations.

A shared presentation helper distinguishes current, updating, invalid, failed and previous-accepted states. Current results provide a brief visual confirmation; reduced-motion settings suppress the animation. The preview retains its accepted ring/graph when input text becomes invalid, while the application state and preview border identify that condition. Input context states whether displayed half-life and horizon values belong to accepted or previous accepted inputs.

The existing quantity editor produced NaN volume metadata when a valid direct-mass event lacked optional volume fields. A reproduced UI workflow verified this defect. The editor now uses zero for absent volume metadata; scientific dose amounts, equations and validation constraints are preserved. The primary body-mass field also keeps a stable accessible name while an error/revert control is present.

Long effects text, BAC band references and clock-reference controls use contextual disclosures in the preview. Peak shortcuts, the selected state and the concentration graph stay prominent. Input context links to Analysis, Explain and Compare, with parameter access at Detailed/Expert and direct scientific/numerical links at Expert.

## Navigation and depth

The existing route resolver is shared with tests. All four scientific child routes keep Analysis and Scientific workbench visibly active. The workbench's existing tab row retains Evaluation, Calibration, Uncertainty and Evidence. Its location line links to observations and reports calibration/evaluation row counts. Analysis offers four named scientific tasks with concise descriptions. Control search includes observations, evaluation, calibration, uncertainty, evidence and parameter configuration, with stable action names.

Default exposes current pharmacological values, concentration definitions and operational instructions. Detailed adds absorption/elimination relationships and directly editable half-life, distribution, gastric-emptying and absorption parameters. Expert retains compact method/provenance text and direct routes to parameters, diagnostics, numerical results and scientific tasks. Contextual parameter dialogs reuse existing validation and Undo. Changing depth performs no scientific document mutation or numerical calculation.

## Concentration inspection

Analysis retains stacked BAC/caffeine plots and the optional overlay. Overlay axis labels identify left BAC and right caffeine scales, with a reserved right margin. Both plots use one inspection time and show cursor dots. Pointer selection/drag, arrow keys, Home/End, Page Up/Down, numeric entry and peak buttons share the existing inspection controller. The slider's accessible value includes time and both concentrations. Accepted intake intervals and analytical markers retain their positions. A labelled configured BAC reference is drawn only when within scale; the reference value is also available as text.

The BAC ring explanation states its quantity and original normalisation: outer fill maps 0–0.25 g/dL, inner fill maps 0.25–0.40 g/dL. Display-unit conversions affect explanatory labels. Severity names remain interpretive concentration bands, with no individual impairment probability implied. Scientific figures retain model lines and conditional P05/P50/P95 bands; quantified measurements use open circles and upper limits use open triangles. No thresholds or scientific algorithms were changed.

## Responsive access

At widths up to 900 px, Analysis presents a compact scenario/action region above the graphs. It exposes body mass, intake count, horizon, Add intake, Edit person, Full input editor and Schedule. The full desktop input rail is replaced by this region at those widths. Complete editing remains one navigation action away. At larger widths the full input rail remains alongside the graphs. Input workspace placement retains the original three-column, two-column and stacked layouts.

## Observation entry and compatibility

Structured entry supports add/edit/remove operations for small datasets. Fields explicitly identify analyte, elapsed or ISO-offset time, measured value, unit, matrix, dataset role, qualifier, optional SD and label. Analyte selection supplies native matrix/unit defaults and clears values whose meaning would change. Alternative matrices require a positive factor and recorded conversion-source assumptions. Field errors appear before commitment. The adapter delegates the final row/document decision to the existing scientific validators, then commits through the scientific controller as one session-history edit.

CSV remains the bulk path, with its schema, atomic replacement and synthetic example preserved. Both entry paths populate the same scientific rows. Existing dataset limits, canonical-unit conversions, error defaults, censoring and held-out semantics remain authoritative. No session or preference schema migration is needed. The v2.0 standalone release remains archived beside the new v2.1 standalone build.

## Verification and remaining usability validation

Node checks add structured/CSV equivalence, explicit-offset timing, field errors, alternative-matrix provenance, edit atomicity, limits, navigation states and exact v2.0 trajectory/default/threshold compatibility. Existing scientific, numerical, state, session and deterministic-build checks remain required.

Three-browser UX workflows cover archetype-aligned tasks, legacy quantity edits, invalid/previous-state previews, parameter access, active navigation and Back/Forward, manual dataset operations, evaluation, search, shared inspection, overlay scales, mobile/tablet actions, modal containment, session compatibility and depth/preference persistence. Screenshots accompany visual checks of the ring and input graph across a navigation round trip. Existing mounted, WCAG, PWA, scientific-workbench and live-deployment suites remain release gates. Hosted verification covers the exact preview and both production origins with cache-controlled reloads and release hashes.

Automated checks establish the covered interaction and accessibility properties. Physical-device installation, assistive-technology task testing and measured first-use cognitive load require manual usability validation.
