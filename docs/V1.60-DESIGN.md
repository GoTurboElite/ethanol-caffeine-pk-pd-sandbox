# v1.60 interface and accessibility scope

Application version 1.6.0 is displayed as release 1.60. This release improves orientation, reading and interaction before v2.0 scientific expansion. Engine 0.4.4, constants 0.3.0 and existing analytical schemas are retained.

## Implemented design contract

| Area | Behaviour |
| --- | --- |
| Orientation | One shell, four primary workspaces, contextual secondary navigation, one main landmark and one visible page title |
| Default analysis | Aligned BAC and caffeine plots with their own labelled scales; consistent solid/dashed traces; shared cursor, event positions and selected time |
| Input access | Reference-person and intake summary beside desktop analysis; quick validated dialogs; links to complete existing editors |
| Calculation identity | One persistent current/pending/failed/invalid status; retained previous results remain identified; manual update and cancellation remain available |
| Progressive disclosure | Optional context, threshold intervals, markers and editing history are collapsible with remembered Standard/Focus states |
| Scientific depth | Default, Detailed and Expert share the same scientific calculation; explanation support, density and reading size are separate choices |
| Parameter access | Search by name/path/unit and a grouped parameter index; direct value editing with validation limits, applicability information and Undo |
| Preferences | Reading, Appearance, Interaction, Units and Profiles; grouped resets, independent profile import/export and explicit storage failures |
| Keyboard and focus | Skip link, visible focus indicators, native modal containment, first-field focus, Escape and focus restoration; Ctrl/Command+K search |
| Responsive access | Wrapped navigation and controls, contained tables, readable SVG labels and layouts sampled from 320 to 1440 pixels |
| Scientific units | Units accompany values; added interactive BAC views convert together; frozen reports and numerical exports declare canonical units |
| Documents and recovery | Named states, portable sessions, browser recovery, frozen reports and interface profiles have separate purposes and labelled controls |
| Offline delivery | Existing worker/cache identity and update-restoration path retained; new hosted and standalone output generated deterministically |

The full intake, physiology, behavioural, sensitivity, numerical and diagnostics interfaces remain available inside the unified shell. Their shared appearance and reading controls are integrated without replacing the calculation authority. The legacy component stays mounted so its hooks and workers retain their lifecycle.

## Defaults and expert use

The initial analysis uses concise support, comfortable spacing, standard reading size and separate concentration plots. Device colour/motion choices are respected. Default scientific depth does not imply a novice reading profile. Expert focus selects Expert depth, concise support, comfortable spacing, reduced motion and collapsed optional context. Each component can subsequently be changed independently.

Context is repeated when it identifies an analytical quantity, unit, horizon or retained snapshot. Duplicate global headers, navigation, large context strips and repeated current-result banners are removed. Detailed and Expert material is available through stable locations; the interface does not automatically rearrange workspaces according to inferred expertise.

## Validation and boundaries

Release gates cover deterministic output, unchanged trajectories, schema round-trips, native downloads, undo/history, three browser engines, keyboard dialogs, preference independence, sampled WCAG rules, responsive containment, standalone delivery and offline update/recovery. Measured results are recorded in RELEASE-VERIFICATION.md and the release pull request.

Automated WCAG checks do not establish complete accessibility conformance. Physical iPhone/iPad installation, screen-reader task testing, browser zoom with assistive technology and observed use by target experts require separate sessions. A reduction in cognitive effort is a design objective; it has not been measured in a user study.

## Subsequent scientific scope

The interface work leaves v2.0 room for explicitly sourced empirical benchmarks, calibration/fitting, population and parameter uncertainty, stronger separation of validated and heuristic outputs, and evidence/provenance expansion. Those additions need their own scientific specifications and validation. They are not introduced by a visual or reading preference.
